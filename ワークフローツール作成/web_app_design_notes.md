# Webアプリケーション化・セキュリティ ＆ 添付ファイル設計提案書

Python ＋ Firebase をベースに、スマートフォンからも安全に承認・決裁を行えるレスポンシブWebアプリケーションの設計提案と前提条件の整理です。

---

## 📱 1. Webアプリ化とスマホ対応（モバイルファースト）

外出先やスマートフォンからでも、片手でタップして「承認」「決裁」「差し戻し」ができるインターフェース（UI/UX）を設計します。

* **フロントエンド技術**:
  * モバイル対応のレスポンシブCSSデザイン（Tailwind CSS またはモダンCSSグリッド）。
  * スマホでの操作性に配慮した「親指で届くボタン配置」「見やすいPDFプレビュー表示」。
* **バックエンド技術**:
  * **Python (FastAPI)**: 超高速で軽量なAPIサーバー。非同期処理に対応しており、同時アクセス耐性を極限まで高めます。

## 📁 2. 添付PDFファイルの保存場所（2つのアプローチ）

Webアプリからアップロードされた稟議書PDFの保存先について、以下の2つの方法を提案します。

| 比較項目 | 選択肢A：Firebase Storage (推奨) | 選択肢B：Google Drive API (継続) |
| :--- | :--- | :--- |
| **特徴** | Firebase標準のオブジェクトストレージ | 現行のGoogle Driveフォルダを継続利用 |
| **メリット** | * 転送速度が極めて高速。<br>* Firestoreとの連携やセキュリティ設定が簡単。<br>* スマホからの表示・アップロードが最適化。 | * 既存のGoogle Driveの容量・階層構造をそのまま使える。<br>* 社員がブラウザやエクスプローラーからDrive内のPDFを直接探せる。 |
| **デメリット** | * 無料枠を超えると従量課金が発生。<br>* 社員が直接フォルダを覗くことができない。 | * Google Drive APIの呼び出し遅延がある（表示がやや遅い）。<br>* APIの認証（認証トークンの維持）の実装が必要。 |
| **提案** | **速度とスマホ動作の快適性を重視するなら「Firebase Storage」が最適**です。社内でGoogle Drive内にPDFを実ファイルとして残しておきたい業務ルールがある場合は、**「Google Drive API」をPythonから叩く構成**を採用します。 |

## 🔒 3. セキュリティ設計

社外（スマートフォン回線など）からのアクセスを想定し、強固なセキュリティを実装します。

```mermaid
graph LR
    User[ユーザー (スマホ/PC)] -->|OAuth 2.0| Auth[Firebase Authentication]
    Auth -->|森林ドメイン制限| Allowed{allowed @forest.co.jp?}
    Allowed -->|Yes| App[Webアプリ / API]
    Allowed -->|No| Block[アクセス拒否]
```

### ① ユーザー認証 (Authentication)
* **Firebase Authentication** を採用。
* **Googleサインイン (OAuth 2.0)** と連携し、会社のGoogleアカウント（`@forest.co.jp`）をそのままログインに使用可能にします（SSO: シングルサインオン）。
* ドメイン制限を設定し、`@forest.co.jp` 以外のメールアドレスは自動的にアクセスを拒否するセキュリティフィルターを構築します。

### ② データベース・ファイルのセキュリティルール (Firebase Rules)
* ログインしたユーザーが「誰か」をFirestoreのSecurity Rulesで検証し、以下の制御をデータベースレベルで強制します。
  * 一般社員：自分の所属する部署の申請、または自分が関係する（申請者・承認者である）稟議ドキュメントのみ読み取り可能。
  * 管理者（`isAdmin == true`）：全データの読み書きが可能。
* 認証されていないリクエストはデータベースから一切データを取得できません。

### ③ 添付ファイルの保護
* 添付PDFファイルのURLには一時的に有効期限を設ける（Signed URL）か、ログイン認証を通したリクエストのみがPDFをダウンロードできるようにFirebase Storage側で制御し、URLの漏洩による情報流出を完全に防ぎます。
