日々の作業を終えた後のプッシュ・プルは、**「自分の作業をクラウド（GitHub）に預け、他のPC（会社PCなど）と同期させるための儀式」**だと考えると分かりやすくなります。

「どういう順番で、何をすれば安全か」を、さらに噛み砕いてマニュアル化しました。

---

## 📅 日々のルーティン：プッシュ・プル完全ガイド

### 1. 【作業開始】まず「もらう」 (Pull)

作業を始める前に、まず最新の状態をGitHubから取り込みます。これを忘れると、後で「競合（コンフリクト）」の原因になります。

* **VS Code**: 左下の **`🔄` (同期アイコン)** をクリック。
* **コマンド**: `git pull origin main`

---

### 2. 【作業中】こまめに「セーブ」 (Commit)

大きな区切りがついたら、こまめにコミット（記録）しておきます。

* **操作**: ソース管理パネルでメッセージを書いて **`✔ コミット`**。
* **コツ**: 「〇〇機能を追加」「バグ修正」など、短いメモを残す。

---

### 3. 【作業終了】最後に「預ける」 (Push)

一日の作業が終わったら、GitHubに自分の成果をすべて送り出します。

#### **★ 安全な終了手順（推奨）**

1. **コミット**: 全ての変更をコミットする。
2. **プル（念のため）**: 他のPCで何か変更していないか、最後に一度プルする。
3. **プッシュ**: 最後に自分の分を送り出す。

* **VS Code**: 左下の **`🔄` (同期アイコン)** をクリック。（これが一番楽です）
* **コマンド**:
```bash
git add .
git commit -m "本日の作業終了"
git pull origin main  # 念のための確認
git push origin main

```



---

## 💡 なぜ「プッシュの前にプル」が必要なの？

もしあなたが個人PCで作業している間に、以前の会社PCでの作業分をプッシュし忘れていた場合、GitHubには「まだ個人PCが知らない古いデータ」が残っていることになります。

そのままプッシュしようとすると、Gitに**「ちょっと待て、GitHub側の方が進んでいるぞ！」（Rejected）**と怒られます。

### **もしエラー（Rejected）が出たら？**

1. 落ち着いて **`git pull`** を実行する。
2. もしVS Codeで「どちらのコードを残すか」聞かれたら、内容を確認して選ぶ（競合解決）。
3. その後、もう一度 **プッシュ** すれば成功します。

## 📝 今日のまとめ（貼り付け用）

```markdown
### 🔄 毎日これだけ！Gitのリズム
- **朝（開始時）**: `git pull` （最新をもらう）
- **昼（区切り）**: `commit` （こまめにセーブ）
- **晩（終了時）**: `git pull` → `git push` （同期して預ける）

※ VS Codeなら、左下の **🔄アイコン** を押すだけで「プル→プッシュ」をまとめてやってくれるので一番安全です。

```

この「朝プル、夜プッシュ」の習慣が身につけば、複数のPCを跨いだ開発でデータが消えたり、古いコードに戻ったりする事故はほぼゼロになりますよ！
