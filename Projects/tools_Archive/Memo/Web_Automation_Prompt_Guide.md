# ブラウザ自動操作アプリ（Selenium等）開発ノウハウ＆プロンプト集

Bizストレージ遅延計測ツール（BizStorage_Delay_Monitor.py）の開発を通じて得られた知見と、今後「同じようなブラウザ操作を自動化するアプリ（RPA）」をAIと協力して作る際に使える強力なプロンプト（指示文）をまとめた資料です。

---

## 1. Bizストレージ遅延計測ツールの開発履歴と成功の鍵（ノウハウまとめ）

今回の開発で「自動化が失敗する壁」をどうやって乗り越えたか、そのノウハウを記録します。今後の開発の基礎となる非常に重要な知見です。

### ① 「ファイル選択」の完全自動化（Seleniumの限界突破）
多くのWebサイトではセキュリティやデザインの都合上、Selenium標準の「ファイルアップロード要素（`<input type="file">`）に対して文字送信する処理」が失敗します。
**【解決策】**
Seleniumで「ファイルを選択」ボタンをクリックさせ、OS（Windows）自体のダイアログが開いたところを `pywinauto` で捕捉。直接 `pyperclip` (クリップボード) を用いて「Ctrl+V + Enter」を叩き込むことで、人間と全く同じ挙動で確実かつ瞬時にファイルをアップロードさせました。

### ② iframe（インラインフレーム）や画面遷移の罠
「絶対に画面上に見えているのに、プログラムがXPathを見つけられない」という現象の原因は、「別の窓（iframe）」の中に要素が潜んでいることでした。
**【解決策】**
`driver.switch_to.frame("SEND_CONTENT")` のように、要素を探す前にAIに「フレーム構造がないか確認し、フレームを切り替えてから操作する」ように指示することが重要です。

### ③ 「すっぽ抜け」と「早すぎる操作」の防止
ロボットは人間の何百倍ものスピードで操作を行うため、Webサイトの裏側（JavaScriptの処理など）が追いつく前に次のボタンを押してしまい、文字抜けや「クリックしたはずが押せていない」すっぽ抜けが発生します。
**【解決策】**
入力フォームを連続で埋める間には `time.sleep(1.5)` を、画面がごそっと切り替わる（確認画面など）時は `time.sleep(5.0)` などの明確な「タメ（待機時間）」を挿入することで、圧倒的に安定性が向上します。

### ④ 解析用ダンプ（デバッグ）機能の実装
エラーの解決を長引かせないための最強の武器です。「なぜ要素が見つからなかったのか？」を人間とAIが瞬時に把握するために作られました。
**【解決策】**
エラーで止まる直前に、**「エラー画面のスクリーンショット」「画面全体のHTMLソース」「その瞬間の全入力要素（ID/Name等）の一覧テキスト」** の3点をログフォルダに出力させることで、原因（サイトの仕様変更か、アカウント制限か、フレーム違いか）が一目瞭然になります。

### ⑤ POP3等のメール連携時の「削除」に注意
メールサーバーにアクセスして自動処理を行う際、「読み取ったメールを消去するのか、残すのか」の設計不足に注意が必要です。
**【解決策】**
自動ツールはあくまで「監視・計測」に徹し、`pop.dele()` を行わずサーバーにメールを残すことで、普段使っているThunderbird等のメーラーの動作を邪魔しない仕組みにしました。

## 2. コピペで使える！次回以降の開発用 AIプロンプト集

今後、別のWebサイトを自動操作するアプリを作る際に、これらのプロンプト（指示）をAIに投げると素早く・確実・安全なコードが返ってきます。

### 🚀 新規にブラウザ操作アプリを依頼するときのプロンプト
```text
Seleniumを使って、指定したWebサイト（URL）を自動操作（ログイン〜データ入力〜実行）するPythonスクリプトを作成してください。
以下の要件を必ず組み込んで安定性を極限まで高めたコードにしてください。
1. 操作が早すぎて文字が抜けたりクリックが空振りするのを防ぐため、各入力・画面遷移の間には必ず time.sleep(1.5 ～ 3.0) 程度の「人間らしい待機時間」を挟むこと。（暗黙的待機だけでは不十分です）
2. ファイルアップロードがある場合は、Seleniumの要素入力ではなく pywinauto と pyperclip（Ctrl+V方式） を使ってWindowsのダイアログに絶対パスを直接入力させる堅牢な方式を採用すること。
3. WebDriverの起動時オプションには、セキュリティソフトの干渉を防ぐための no-sandbox 引数などを含めること。
```

### 🔍 「要素が見つからない」エラーが出たときのデバッグ用プロンプト
```text
要素（XPathやID）が見つからずに TimeoutException が発生しています。原因特定のため、コードに以下のデバッグ機能を追加してください。
1. エラーで落ちた直前の「画面全体のHTMLソース（page_source）」をデスクトップに保存する。
2. その時画面に存在するすべての input, button, textarea 等の要素のタグ名とID、Name属性をテキストに抽出して保存する。
3. エラー時のスクリーンショットも一緒に保存する。
まずは上記の仕組みを組み込んだコードを発行し、そのダンプ結果を見てから本解決の修正を行います。
```

### 🛡️ 想定外の画面（エラーや制限）に対応させるプロンプト
```text
ログイン画面や途中の処理で、サイト側から「アカウントロック」「上限エラー」「メンテ画面」などの警告文が表示される可能性があります。
操作対象の要素が見つからないというエラーになる前に、指定のボタンをクリック後「画面上に明らかなエラーや警告テキストが表示されていないか」をチェックし、見つかった場合はログに出力して処理を安全に中断する機能を組み込んでください。
```

### 📦 exe化（PyInstaller）する際のプロンプト
```text
作成したPythonスクリプトをPyInstallerでexe化します。Seleniumやpywinautoなど、動的に読み込まれるモジュールが不足してexe実行時にエラーになるのを防ぐため、必要な --hidden-import オプション（selenium.webdriver.edge.webdriver, selenium.common.exceptions, pyperclip など）を網羅した実行用コマンド（batまたはps1形式）を提示してください。
```
