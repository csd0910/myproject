# Bizストレージ遅延計測ツール (BizStorage Delay Monitor) 技術仕様書

## 1. システム概要
本システムは、「Bizストレージ ファイルシェア」のファイル送信機能を用いた際の遅延時間（Web画面から送信完了する時刻と、受信者側でメールを受信する時刻の差）を自動で計測・記録するためのモニタリングツールです。

完全な自動稼働を前提として設計されており、Windows環境で定期的に送信処理と受信判定を行い、その結果をCSVログとして出力します。

## 2. 実行環境・使用技術
*   **動作環境:** Windows 10 / 11 (エクスプローラのファイルダイアログ操作が依存しているため)
*   **開発言語:** Python 3.12+
*   **主要ライブラリ:**
    *   **Selenium (Edge Driver稼働):** BizストレージのWeb画面の自動操作・スクレイピング。
    *   **pywinauto:** Seleniumから直接干渉できないWindowsネイティブの「ファイル選択ダイアログ」に対し、ファイルパスのキーボード入力をシミュレート。
    *   **poplib / email:** POP3プロトコルでの受信メールボックスの監視、件名と送信時刻(Dateヘッダ)の解析。
    *   **PyInstaller:** Python環境がない別PCへの配布のため、単一の実行可能ファイル(`.exe`)へパッケージング。

## 3. 主要な定数・設定値 (スクリプト上部にて定義)
| 変数名 | 説明 | デフォルト値 |
| :--- | :--- | :--- |
| `WEB_URL`, `WEB_ID`, `WEB_PASS` | Bizストレージのログイン情報 | - |
| `UPLOAD_FILE_PATH` | 送信するダミーファイルの絶対パス | - |
| `DEST_EMAIL`, `SENDER_NAME` | 送信先アドレス、差出人名情報 | - |
| `POP_SERVER`, `POP_PORT`, etc. | 検知用メールボックスのPOP3情報 | - |
| `LOG_FOLDER_NAME`, `LOG_FILE_NAME` | 結果を出力するCSVの保存先(デスクトップ直下) | `BizStorage_Log\evidence_log.csv` |
| `LOOP_INTERVAL_MINUTES` | 次回の検査までの待機インターバル | 10 (分) |
| `START_HOUR`, `END_HOUR` | スクリプトが稼働する時間帯 | 8〜19 (時) |

## 4. 処理フロー
本システムは `[8:00 - 19:00]` の稼働時間帯において、指定されたインターバルで以下のサイクルを無限ループします。

### Step 1: Web送信処理 (`execute_web_transmission`)
※ **全体リトライ機能**: このStep 1の一連の処理中に何らかのエラー（タイムアウト等）が発生した場合、直ちには諦めず、10秒待機した上で**最大3回まで**最初から処理をやり直す仕組みになっています。

1.  **ログイン**: IDとパスワードを使用してBizストレージへログイン。
2.  **画面遷移**: 共有ディスク > ファイル送信画面へ移動。
3.  **ファイルアップロード(特殊処理)**:
    *   「ファイル選択」ボタン(`id="uploadFiles"`)をクリック。
    *   Windowsダイアログが開くのを待ち、`pywinauto` を用いてフォーカスされているファイル名入力欄へパスの文字列と `{ENTER}` キーを送信。
    *   *(※キー入力がPCの負荷等で取りこぼされた（失敗した）場合も、2秒待機して**最大3回まで**入力をリトライします)*
4.  **フレーム切り替え**: その後の宛先指定などはHTML上のインラインフレーム(`<iframe>`)内に存在するため、Seleniumの操作コンテキストを `SEND_CONTENT` フレームへ切り替え。
5.  **情報入力と送信結果の取得**:
    *   宛先、件名を `name` 属性などを基準に入力。
    *   送信確認画面を経て送信実行ボタン(`id="contentComfirm"`)を押下。
    *   送信完了時点のシステム時刻を **T1** として記録。

### Step 2: メール受信監視 (`monitor_pop_mail`)
1.  **POP3接続**: Web送信完了後、速やかにPOP3サーバーへ接続。
2.  **ポーリング**: 最大15分間、30秒間隔でメールボックス内の最新メッセージを走査。
3.  **検知と時刻記録**:
    *   Step1で生成された一意の「件名(`[Biz遅延計測自動テスト] MMDD_HHMMSS`)」が含まれるメールを検知。
    *   検知時点のシステム時刻を **T2** として記録。
    *   メールのヘッダ(`Date`)から、サーバー通過時刻 **T_Hdr** を取得。
4.  **クリーンアップ**: 検知した測定用テストメールをサーバー上から削除(`pop.dele`)。

### Step 3: 結果出力 (`write_log`)
T1とT2の差分(秒数)を計算し、実行時のデスクトップに存在する `evidence_log.csv` へ結果を追記。
エラー時は `TIMEOUT_NO_MAIL` または `ERROR_WEB_TRANSMIT` のステータスが記録されます。

## 5. 既知の制限事項・注意点
*   **画面ロック状態での制限:** `pywinauto` はWindowsのデスクトップUIを操作するため、画面ロック中やRDP切断中など、アクティブなデスクトップセッションが存在しない状態ではファイル選択処理が失敗する可能性があります。
*   **Selenium要素の変更耐性:** XPathの構造変更に対する脆弱性を回避するため、極力 `id` や `name` 属性を用いて要素を特定しています(2026/03/03改修)。しかし、Bizストレージの大規模なシステムアップデートがあった場合は、ロケーターの再定義によるメンテナンスが必要となります。

## 6. EXEのビルド(パッケージング)手順
別PCへの移行時には、以下の `PyInstaller` コマンドで実行ファイルを生成します。
SeleniumとそのWebDriver仕様を暗黙のうちに完全に梱包するため `--collect-all selenium` を指定することが必須です。

```bash
cd c:\Users\フォーレスト026\MyProject\MyProject\tools\TEST
pyinstaller --onefile --collect-all selenium BizStorage_Delay_Monitor.py
```
> ※出力された `.exe` ファイルは `dist` フォルダ内に格納されます。

## 7. Pythonプログラミングと改修時の基礎知識（開発初心者向けガイド）

本プログラム（または新しいPythonスクリプト）を作成・修正していく際の「基本的な考え方」と「開発手順」をまとめました。

### 7.1. プログラムを書く際の手順
開発は一度に全てを作ろうとせず、小さな機能ごとに作成してテスト（デバッグ）を繰り返すのが基本です。

1.  **目的の明確化と処理の分割**
    *   「何を実現したいか」を整理し、「Aをして」「Bをして」「Cをする」と細かくステップに分けます。
    *   例：「Webサイトを開く」→「ログインする」→「ボタンを押す」
2.  **部分ごとのコード実装（コーディング）**
    *   処理の最初の部分（例：Webサイトを開く部分だけ）のコードを書きます。
3.  **部分テストの実施**
    *   書いた部分までが正しく動くか、実際にプログラムを実行して確認します（デバッグ実行）。
    *   必要に応じて `print()` 文を使い、変数の中身や「今どこまで処理が進んでいるか」を画面に出力するとエラーの原因を特定しやすくなります（本プログラムでも随所で `print_timestamp("...")` を活用しています）。
4.  **エラー対応と修正**
    *   エラーが出たらエラーメッセージを確認します。どこで（何行目で）、なぜ止まったのかが書かれています。
    *   今回は「要素が見つかりませんでした」というエラーであったため、HTML要素（`id` や `name` など）を調べてコードを修正しました。
5.  **上記の繰り返し**
    *   「書いて、部分テストして、修正する」を繰り返し、全ての処理を繋げて完成させます。

### 7.2. Pythonの基礎的な文法とルール
Pythonスクリプトを読み書きする上で、最低限知っておくべき共通ルールです。

*   **インデント（字下げ）によるブロック表現**
    *   Pythonは、行の先頭の「空白（通常は半角スペース4つ）」で処理のかたまり（ブロック）を表現します。
    *   `if`（条件分岐）や `for`（繰り返し）、`def`（関数定義）の次の行は一段字下げする必要があります。字下げがズレるとエラーになります。
    *   ```python
        if 条件:
            # ここは条件が成立したときだけ実行される
            print("OK")
        # 字下げが終わるとブロック外となり、常に実行される
        ```
*   **変数（データを一時的に保存する箱）**
    *   データ（文字や数値など）には名前をつけて保存できます。
    *   `WEB_URL = "https://..."` は、`WEB_URL`という箱にURLの文字を入れていることを意味します。
*   **コメント（プログラムとして実行されないメモ）**
    *   `#` から始まる文字はコメントです。プログラムの動作には影響しないので、処理の説明やメモ書きに自由に使えます。コードを書く際は、後で見たときに「何をしている処理か」が分かるようにコメントを多めに残すことが大切です。
*   **関数の定義（よく使う処理をまとめる）**
    *   `def 関数名():` という書き方で、ひとまとめの処理に名前を付けられます（本プログラムの `def execute_web_transmission():` など）。これを「関数」と呼びます。
    *   関数を作っておけば、別の場所から「関数名()」と書くだけでその処理を呼び出して実行でき、プログラムがスッキリします。
*   **モジュールのインポート（拡張機能の読み込み）**
    *   スクリプトの先頭にある `import os` や `from selenium import webdriver` などは、Pythonの基本機能にはない「便利な道具箱（ライブラリ）」を読み込むための記述です。これによって複雑な処理（ブラウザ操作など）が簡単に使えるようになります。

### 7.3. 自動化（Selenium）特有の基礎知識
Web画面を自動操作する上で、知っておくべき考え方です。

*   **HTMLの要素（エレメント）を特定して操作する**
    *   画面上のボタンや入力欄を操作するには、「どの部品を操作するか」をプログラムに指示する必要があります。
    *   基本は、対象の部品が持つ「固有の名前（`id`属性や`name`属性）」を使って特定します（例：`By.ID, "uploadFiles"`）。
    *   `id`・`name`が無い場合は、階層構造を辿る「XPath（エックスパス）」という方法を使いますが、画面デザインが少し変わるだけでパスがズレて動かなくなるため、最終手段として使います。
*   **待機（Sleep / Wait）の重要性**
    *   プログラムは非常に高速に動くため、画面の読み込み（ネットワーク通信やアニメーション）が完了する前に次の操作をしようとしてエラーになることが多々あります。
    *   そのため、「画面が出るまで少し待つ（`time.sleep(2)` 等）」という処理を挟むことが重要です。本プログラムでは、要素が現れるまで自動で待つ `WebDriverWait` という高度な待機処理も組み合わせて安定させています（`safe_click` 関数など）。
