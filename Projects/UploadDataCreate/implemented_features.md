# UploadDataCreate ツール 実装済み機能・仕様一覧

本ドキュメントは、現在までにPython（`gui.py` / `main.py`）で実装が完了している機能と、各工程の具体的な処理仕様をまとめたものです。

## 1. システム全体機能（UI・操作性）

* **対話型ウィザードGUI (`gui.py`)**
  * 画面左側に全8工程の「処理フロー」を常時表示し、現在の進捗（未実行・実行中・完了済）を色付きで可視化。
  * 画面右側にチャットボット風の案内エリアを設け、処理ごとの「除外件数」や「次のアクション」を人間が読みやすい文章で案内。
* **対象ファイルの自動検出**
  * アプリ起動時に、指定フォルダ（`Desktop\元データ` 等）から `result_*.xlsx` を自動的に探し出してテキストボックスにセットし、ユーザーのファイル探しの手間を削減。
* **中間ファイル出力機能**
  * 各ステージ（1〜8）の処理が終わるごとに `temp_stageX.xlsx` として中間状態を自動保存。UI上のボタンから即座にExcelを開いて中身の「答え合わせ（目視確認）」が可能。

## 2. バックエンド処理ロジック（全8工程）

現在、以下のデータ加工ロジックが `main.py` 内にすべて実装完了しています。

### Stage 1: 更新除外データの削除
* **参照**: `【2】社外キーワード追加対応.xlsx`
* **処理**: ベースデータの「品目cd(C列)」および「注文番号(D列)」をキーとしてVLOOKUPを行い、参照ファイル側に存在する完全一致の行を、ベースデータから除外（削除）する。

### Stage 2: 取り寄せ品の除外（※欠損工程3・4を統合済み）
* **参照**: `111取り寄せ＋有効在庫有り.xlsx (または.csv)`
* **処理**:
  1. 参照ファイル内で「有効在庫数(C列)」が `0` のものを除外。
  2. 参照ファイル内で「未引当て数量(G列)」が `1` 以上のものを除外。
  3. 上記の厳しい条件をくぐり抜けて「生き残った」商品コードを抽出し、ベースデータ側の品目cdと突き合わせて、該当する行をベースデータから一気に除外する。

### Stage 3: 医薬品の除外
* **処理**: ベースデータの「品目大分類cd(AG列)」が `40` （医薬品）となっている行をすべて除外する。

### Stage 4: 特定文字列の削除
* **処理**: ベースデータの「足し算列(U列)」に入っているテキストの中から、`【指定第2類医薬品】` と `【第2類医薬品】` という特定のタグ（文字列）を検索し、存在する場合は空文字に置換（削除）する。

### Stage 5: 送料無料の付与 (楽天用)
* **処理**: 「倉庫cd(O列)」が `2` である行を探し、その行の「送料区分2(I列)」の値を強制的に `送料無料` というテキストで上書きする。

### Stage 6: イベント別キーワード付与 (動的シート分割)
* **参照**: `events.json` および 各イベント名のCSV（例: `うんちょ.csv`）
* **処理**:
  1. 設定ファイル（JSON）に登録されたイベント名と同名のCSVを自動で読み込む。
  2. CSV内の注文番号と一致するデータだけをベースデータから抽出。
  3. 抽出したデータの「足し算列(U列)」の先頭に、イベント用のキーワード（例: `【目玉商品】 `）を付加する。
  4. イベント対象となったデータだけを切り出し、後続処理（Stage7）へと引き継ぐ。

### Stage 7: 文字数制限の調整 (楽天: 255バイト制限)
* **処理**:
  * 楽天の仕様（全角2バイト、半角1バイト）に合わせて、Stage6でキーワードが付加された「足し算列(U列)」のバイト数を厳密に計算。
  * 255バイトをオーバーしている場合、255バイト以下に収まるまで「末尾の文字」から1文字ずつ削り落とす（カット処理）を全自動で行う。

### Stage 8: 最終フォーマット調整
* **処理**:
  * ここまでの加工を終えたデータを抽出し、アップロード用の最終フォーマット（`normal_item_result.xlsx`）に変換する。
  * **商品管理番号**: 「注文番号」をすべて小文字（`LOWER`）に変換し、降順（Ｚ→Ａ）で並び替える。
  * **商品名**: キーワード付加・文字数カット済みの「足し算列」を転記する。
  * **採番**: 出来上がったリストの上から順に 1, 2, 3... と連番を割り当てる。
  * Stage6で分割・抽出された各イベントごとに、**別々のExcelファイルとして出力**します。
  * 出力される各ファイル名は `normal-item_rc[イベント名].xlsx` （例：`normal-item_rcうんちょ.xlsx`）となります。

## 3. システム安全対策（目に見えない裏側の工夫）

* **大容量データ時のフリーズ防止（非同期処理）**
  * 数十万件のデータをExcelに出力（`to_excel`）する際は数分間の負荷がかかります。この間、画面が「応答なし」になってパニックを引き起こさないよう、重い処理を裏側（別スレッド / threading）に逃がし、画面上では緑色の待機スピナー（プログレスバー）が動いて「現在処理中であること」を明示する安全設計にしています。
* **設定ファイル(JSON)のエラー耐性**
  * 現場担当者がJSONを手動で編集した際、カンマの付け忘れ等で構文エラー（JSONDecodeError）になってもアプリ全体がクラッシュしないよう、GUI上に「設定ファイルの記述に誤りがあります」と警告を出した上で、安全なデフォルト値（空の設定）にフォールバックして処理を続行する仕組みを採用しています。
* **列名のズレ自動追従**
  * Excel特有の「列の挿入・削除による列ズレ」が起きてもパニックを起こさないよう、まずは1行目の「ヘッダ名（列名）」を探してインデックスを自動特定する処理を組み込んでいます。
* **文字コードの自動回避**
  * 古いシステムから出力されたCSVによくある「Shift-JIS」や、BOM付きの「UTF-8」など、厄介な文字コードの違いをプログラムが自動判定して読み込む安全装置（`read_csv_safe`）を搭載しています。
* **空ファイル対策**
  * 現場担当者が誤って中身が空のCSVを置いてしまっても、システムがクラッシュせずに「0件として処理をスキップ」する保護機能を実装しています。
