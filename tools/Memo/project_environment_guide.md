# プロジェクト環境ガイド

このプロジェクトのディレクトリ構造の意味と、開発時の同期ルールをまとめます。

## 1. ディレクトリ構造の役割（「キッチン」のイメージ）
プロジェクト全体を「料理を作る場所」に例えると分かりやすくなります。

| フォルダ/ファイル | イメージ | 役割・使い道 |
| :--- | :--- | :--- |
| **`app/`** | **メインのキッチン** | 本番の料理（プログラム）を作る場所。 |
| **`data/`** | **冷蔵庫・パントリー** | 材料（CSVやデータ）を保管しておく場所。 |
| **`tools/`** | **便利な調理器具棚** | メモや補助的な道具（スクリプト）を置く場所。 |
| **`TEST/`** | **試作コーナー** | 新しいレシピをこっそり試す場所。 |
| **`.venv/`** | **シェフの調理道具一式** | その料理専用の包丁や鍋。PCごとに用意します。 |
| **`.gitignore`** | **ゴミ箱・隠し扉** | 外に見せたくないものや不要なものを隠す設定。 |
| **`requirements.txt`** | **材料リスト（お買い物表）** | 他のPCでも同じ味を作るための「必要なもの一覧」。 |

---

## 2. 開発時の同期ルール

### A. 一般ファイル（.py, .md, .txtなど）を更新したとき
「荷物を箱に詰めて、宛先を書いて、発送する」イメージです。

1.  **荷造り（ステージング）**: `git add .`
    - **イメージ**: 発送したいファイルを「段ボール箱に入れる」作業です。
2.  **封をしてラベルを貼る（コミット）**: `git commit -m "変更内容のメモ"`
    - **イメージ**: 箱のガムテープを止め、中身が何か（メモ）を書いて「発送待ち状態」にする作業です。
3.  **発送（プッシュ）**: `git push origin main`
    - **イメージ**: 荷物を「郵便局（GitHub）に持っていき、世界に送る」作業です。

### B. ライブラリ（venv環境）を更新したとき
「必要な材料リスト（お買い物表）」を更新して共有するイメージです。

1.  **リスト更新（お買い物表を書く）**: `pip freeze > requirements.txt`
    - **イメージ**: 今使っている調味料をリストアップして、紙に書き出す作業です。
2.  **Git送信（リストを渡す）**: `requirements.txt` を含めて `git push`
    - **イメージ**: その書き出したリストを、他のPC（相方）に送る作業です。
3.  **別PCでの反映（材料を買ってくる）**: `pip install -r requirements.txt`
    - **イメージ**: リストを受け取った側が、スーパー（インターネット）から一括で買い出しをする作業です。

---

## 3. なぜこの構造にするのか？
-   **整理整頓**: 「本番」「データ」「実験」を分けることで混乱を防ぎます。
-   **環境再現性**: 他のPCでも `git clone` して `pip install` するだけで、すぐに開発が再開できます。
---

## 4. 全体イメージ図（可視化）

```text
[あなたのPC]                          [GitHub（郵便局）]
      |                                      |
      |  (1) git add . (荷造り)              |
      |  (2) git commit (封印)               |
      |  (3) git push (発送) --------------> [保管]
                                             |
[別のPC]                                     |
      |                                      |
      |  (4) git pull (受取) <--------------- [取得]
      |  (5) pip install (買い出し)
```
