# プロジェクト環境ガイド

このプロジェクトのディレクトリ構造の意味と、開発時の同期ルールをまとめます。

## 1. ディレクトリ構造と役割

| フォルダ/ファイル | 役割・意味 | 使い道 |
| :--- | :--- | :--- |
| **`app/`** | **メインプログラム** | 完成版として動かすソースコードを置く場所。 |
| **`data/`** | **データ保管庫** | CSVやJSONなど、プログラムが読み書きするデータを置く場所。 |
| **`tools/`** | **開発補助ツール** | メモや補助スクリプト、AIの設定などを置く場所。 |
| **`TEST/`** | **実験・テスト場** | 一時的な機能テストや試作コードを置く場所。 |
| **`.venv/`** | **仮想環境** | Python本体とライブラリの実体。PCごとに作成する（Git対象外）。 |
| **`.gitignore`** | **管理設定** | Gitに上げたくないファイルを指定する設定ファイル。 |
| **`requirements.txt`** | **環境のレシピ** | 他のPCで同じライブラリ環境を再現するためのリスト。 |

---

## 2. 開発時の同期ルール

### A. 一般ファイル（.py, .md, .txtなど）を更新したとき
1.  **ステージング**: `git add .`
2.  **コミット**: `git commit -m "変更内容のメモ"`
3.  **送信**: `git push origin main`

### B. ライブラリ（venv環境）を更新したとき
`pip install` で何かを追加した際は、以下の手順で同期します。
1.  **リスト更新**: `pip freeze > requirements.txt`
2.  **Git送信**: `requirements.txt` を含めて `git push`
3.  **別PCでの反映**: `pip install -r requirements.txt` (venv有効時)

---

## 3. なぜこの構造にするのか？
-   **整理整頓**: 「本番」「データ」「実験」を分けることで混乱を防ぎます。
-   **環境再現性**: 他のPCでも `git clone` して `pip install` するだけで、すぐに開発が再開できます。
-   **安全性**: 本番コード（`app`）を実験用コード（`TEST`）から分離し、意図しない破壊を防ぎます。
